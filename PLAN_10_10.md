# Plan d'Attaque — Autonomie 10/10

**Score actuel : 7/10 — Cible : 10/10**

---

## Définition 10/10

Un agent qui :
- Reçoit un objectif vague → le décompose, planifie, exécute sans intervention humaine
- Récupère seul de toute erreur (crash, LLM down, sandbox fail, OOM)
- Apprend en continu : skills, SOPs, connaissances, patterns
- S'auto-héberge : backup, rollback, mise à jour, monitoring
- Interagit en langage naturel avec n'importe quel humain
- Justifie chaque décision avec un chaîne de raisonnement vérifiable
- Survit 30 jours sans redémarrage ni dégradation

---

## PHASE 5 — Résilience & Auto-Réparation (7→8) — 1 semaine

### 5.1 Self-healing infra
- **Watchdog matériel** : si GPU/Ollama/disk tombe → tente restart systemd, log dans audit, continue en mode dégradé
- **Auto-restart des crates** : si un sous-système plante → le daemon le respawn
- **Graceful degradation** : si LLM indisponible → fallback mode stub + notify, pas de crash
- **Disk pressure handling** : si disk > 90% → purge auto des logs/checkpoints vieux, alert

### 5.2 Checkpoint & Rollback automatique
- Checkpoint toutes les 100 cycles ReAct + avant chaque opération destructive
- Rollback automatique si le système détecte une dégradation (memory health < seuil)
- Git auto-commit des modifications de code auto-générées

### 5.3 Tests de résilience (chaos engineering)
- `soul-chaos` déjà existant : l'activer en mode production (injection latency/error/corrupt/kill)
- Test de survie 7 jours sans intervention

---

## PHASE 6 — Apprentissage Continu (8→9) — 2 semaines

### 6.1 SOP Registry & Discovery
- `soul-automodify` + `soul-skills` bridge finalisé
- **SOP Crystallization** : après 3 exécutions réussies d'un pattern similaire → SOP auto-générée
- **Skill fusion** : 2 skills similaires → fusion automatique
- **Skill pruning** : skill non utilisé depuis 30 jours → archivage

### 6.2 Fine-tuning pipeline actif
- `soullink-trainer` déja existant : le connecter en boucle
- Collecter trajectoires ReAct → filtrer les réussites → exporter paires DPO
- Lancer un fine-tuning toutes les 1000 tâches réussies
- Versionner les modèles fine-tunés

### 6.3 Meta-cognition active
- `soullink-autonomy::metacognition` déjà existant : l'activer
- **Self-model** : l'agent maintient un modèle de ses propres capacités/limites
- **Strategy selection** : choisir la stratégie (ReAct, Tree-of-Thoughts, Plan-rétro) selon le type de tâche
- **Confidence calibration** : l'agent estime sa confiance et demande de l'aide si < seuil

### 6.4 Knowledge Graph auto-alimenté
- `soul-graph-memory` (fusionné dans `soul-memory`) : activer la popuilation automatique
- Chaque tâche → nœud `Task` + relations `DependsOn`/`SolvedBy`
- Chaque skill → nœud `Skill` + relations `Uses`/`Implements`
- Requête auto du graphe pour le contexte ReAct

---

## PHASE 7 — Interaction & Justification (9→10) — 2 semaines

### 7.1 Chaîne de raisonnement vérifiable
- Chaque décision → `DecisionRecord { goal, options_considered, chosen, rationale, confidence }`
- Stocké dans le graphe de connaissances
- Exportable en Markdown/JSON pour audit humain

### 7.2 Dialogue naturel fluide
- `soul_repl` amélioré : contexte de conversation infini (compression + résumé)
- Mémoire des préférences utilisateur persistée
- Style adaptatif (technique / vulgarisé selon l'interlocuteur)
- Notifications proactives : "J'ai remarqué que X, je propose Y"

### 7.3 Auto-documentation
- L'agent documente ses propres découvertes
- Génération automatique de `LEARNINGS.md` à chaque milestone
- CHANGELOG auto-généré

### 7.4 Survie 30 jours
- Test : l'agent tourne 30 jours sans redémarrage
- Aucune fuite mémoire (vérifié par `soullink-vram`)
- Aucune dérive de performance (vérifié par `MemoryHealth`)
- Capacité à gérer son propre stockage (purge, backup, compaction)

## Risques & Mitigations

| Risque | Probabilité | Mitigation |
|--------|------------|------------|
| Fine-tuning consomme trop de VRAM | Haute | Déléguer à un job hors-pic, utiliser `soullink-vram` pour scheduler |
| SOP crystallization génère du bruit | Moyenne | Seuil de qualité : seulement si critique score > 7/10 |
| Fuite mémoire après 30 jours | Moyenne | `soul-chaos` memory leak test en amont, `soullink-vram` monitoring |
| Community building trop lent | Haute | Accepter que SoulSystem reste un projet solo — miser sur la qualité technique |

## Commandes Clés

```bash
# Lancer la boucle autonome
cargo run --bin soulsystem -- --daemon

# Lancer les chaos tests
cargo run -p soul-chaos -- --mode production

cargo run -p soulsystem -- --audit
```
