## The Problem: Filesystem Marker Pattern

### Previous Implementation
```typescript
// Complex state tracking via filesystem markers
async writeLaunchAgentDisableMarker(): Promise<void>
async hasLaunchAgentDisableMarker(): Promise<boolean>
async clearLaunchAgentDisableMarker(): Promise<void>
async enableLaunchAgentIfOwnedStop(): Promise<void>
```

**Issues:**
- Race conditions between marker writes/reads
- Orphaned markers after crashes
- No single source of truth
- Difficult to debug

---

## The Solution: Idempotent launchctl Operations

### New Implementation
```typescript
// Simplified - always use launchctl as source of truth
async execLaunchctl(args: string[]): Promise<ExecResult>

// Enable service (idempotent)
await execLaunchctl(["enable", serviceTarget]);

// Bootstrap and kickstart as needed
await execLaunchctl(["bootstrap", domain, plistPath]);
await execLaunchctl(["kickstart", "-k", serviceTarget]);
```

**Benefits:**
- Single source of truth: `launchctl` state
- No filesystem race conditions
- Self-healing after crashes
- 149 lines removed

## Key Architectural Decisions

### 1. Domain Selection
```typescript
// Uses gui/$UID domain for user-scoped agents
const domain = `gui/${uid}`;
```

**Rationale:** 
- User-scoped daemons don't require root
- Follows macOS best practices
- Isolates per-user OpenClaw instances

### 2. Label Validation
```typescript
// Enforces strict label format
assertValidLaunchAgentLabel(label: string): void
// Regex: [A-Za-z0-9._-]+
```

**Protection:**
- Prevents injection attacks
- Ensures launchctl compatibility

### 3. Handoff Pattern
```typescript
// Self-restart via detached handoff process
// Survives kickstart -k (kill)
```

**Implementation:**
- Detached process survives parent termination
- Handoff process restarts service
- Clean handover without downtime
