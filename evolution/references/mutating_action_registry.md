# Mutating Action Registry Pattern

## Problem

When GPT-5 agent retry behavior was split from prompt construction (#65597), the question arose: which actions are "mutating" and should NOT be replayed on retry? Currently this is determined ad-hoc in prompt overlays and retry logic, creating risk of divergence between the two.

## Proposed Pattern: Mutating Action Registry

```typescript
// src/agents/action-registry.ts
const MUTATING_ACTIONS = new Set([
  'sessions_spawn',    // Creates a new session
  'message_send',      // Sends a message externally
  'cron_add',          // Creates a cron job
  'cron_remove',       // Removes a cron job
  'gateway_config_patch', // Modifies gateway config
  'exec_elevated',     // Elevated command execution
  'message_react',     // Emoji reaction (visible externally)
  'message_delete',    // Deletes a message (irreversible)
]);

function isMutating(action: string): boolean {
  return MUTATING_ACTIONS.has(action);
}
```

## Benefits

1. **Single source of truth** — Both prompt construction and retry logic query the same set
2. **Compile-time safety** — Missing actions are caught in code review, not at runtime
3. **Testability** — Can unit test that all tool actions are classified as mutating or idempotent
4. **Extensibility** — Adding a new tool? Just add it to the registry

## Integration Points

- `resolveEffectiveExecutionContract()` — uses this to determine which actions need fail-closed retry
- `prompt-overlay.ts` — uses this to inject "do not retry" instructions per action
- Agent harness — uses this to decide whether to replay or skip on retry
